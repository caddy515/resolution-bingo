Apple rejected the app because it supported account creation but did not offer in-app account deletion.

Reviewer guidance required:

- Users must be able to initiate account deletion.
- Temporary deactivation is not enough.
- If deletion requires the web, the app must link directly to the deletion page.
- The complete deletion flow must be demonstrated in a screen recording on a physical device and attached in App Review Notes.

### 2. Firestore permission bug fixed

During testing, account deletion initially failed with:

- `Missing or insufficient permissions`

Cause:

- The code attempted to delete the parent Firestore document at `/users/{uid}`.
- Firestore rules explicitly deny writes on `/users/{uid}` and only allow card operations on `/users/{uid}/cards/{cardId}` for the owner.

Fix:

- Removed the attempted delete of the parent `/users/{uid}` document.
- Now `deleteAllUserData(uid)` only deletes the user's card documents.

Relevant files:

- [src/firebase/firestore.js](/Users/evanluscher/resolution-bingo/src/firebase/firestore.js)
- [firestore.rules](/Users/evanluscher/resolution-bingo/firestore.rules)

## Input/autofill issue history

### Problem

There were repeated reports of form fields turning yellow and behaving poorly on iPhone/TestFlight. This affected:

- signup password fields when using Apple's strong password autofill
- after signup, the builder screen fields like:
  - `Card title`
  - `Create a new category`

Important note:

- This issue seemed more reproducible in TestFlight/physical device than in simulator.
- Simulator testing did not fully reproduce the production-device behavior.

### Changes made to address it

Applied a broad input hardening pass across screens with `TextInput`s:

- [src/screens/LoginScreen.js](/Users/evanluscher/resolution-bingo/src/screens/LoginScreen.js)
- [src/screens/SignupScreen.js](/Users/evanluscher/resolution-bingo/src/screens/SignupScreen.js)
- [src/screens/ForgotPasswordScreen.js](/Users/evanluscher/resolution-bingo/src/screens/ForgotPasswordScreen.js)
- [src/screens/BuilderScreen.js](/Users/evanluscher/resolution-bingo/src/screens/BuilderScreen.js)

Changes included:

- `keyboardShouldPersistTaps="handled"` on relevant `ScrollView`s
- explicit `autoComplete` handling
- explicit `textContentType` handling
- `importantForAutofill="no"` where appropriate
- `spellCheck={false}` where appropriate
- `editable={!loading}` on auth fields
- `Keyboard.dismiss()` before auth submits and navigation actions
- `Keyboard.dismiss()` when the builder screen mounts

Additional note:

- Password fields were changed to use `textContentType="oneTimeCode"` as an aggressive workaround to suppress iOS password autofill styling/state leakage into subsequent forms.

### Testing outcome at last check

- Account deletion flow was verified working in iOS simulator.
- Input yellowing was still believed to be a physical-device/TestFlight-sensitive issue and should be retested on the latest submitted build.
